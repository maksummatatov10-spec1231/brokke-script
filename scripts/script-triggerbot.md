# ScriptTriggerBot — прототип 0.1.0

Файл: [script-triggerbot.kts](script-triggerbot.kts).

## Совместимость и статус

Написан по `API.md`, `API_REFERENCE.txt` и примерам из этого репозитория, API 4.
Minecraft 26.3 — целевая версия со слов владельца. Совместимость конкретной сборки Brokke с этим API здесь не проверена. Компилятора окружения Brokke и запущенного клиента в репозитории нет: это **не проверенный в игре релиз**.

Использовать в одиночной игре или там, где автоматизация разрешена. Скрипт не обходит античит, не меняет серверную дальность и не гарантирует принятие ударов сервером.

## Установка

1. Скопировать только `script-triggerbot.kts` в `.minecraft/brokke/scripts`.
2. Дождаться компиляции во вкладке «Скрипты». При ошибке сохранить полный текст со строкой.
3. В ClickGUI открыть Combat → **ScriptTriggerBot**, ПКМ — настройки, ЛКМ — включение. Бинд назначить средствами клиента.
4. Отключить встроенный TriggerBot, Aura и другие атакующие модули на время проверки. Они могут давать дополнительные удары независимо от условий этого скрипта.

По документации модуль независим от включателя скрипта. Выключать нужно **ScriptTriggerBot в ClickGUI**.

## Настройки

- **Цели:** мультивыбор игроков, монстров, животных, других живых и неживых сущностей. Пустой выбор запрещает все атаки. Категории определяются классификацией API, не списком вручную.
- **Фильтр ID:** выключен / белый / чёрный список. ID через запятую; `zombie` нормализуется в `minecraft:zombie`. Белый список с пустым полем запрещает все цели. Фильтр дополнительно ограничивает выбранные категории, не заменяет их.
- **Бить друзей / невидимых / ботов / стойки:** отдельные разрешения, по умолчанию выключены. Классификация ботов и друзей зависит от клиента. Для стойки нужно также разрешить её категорию.
- **Дальность:** 0.5–6 блоков по расстоянию до точки пересечения луча с хитбоксом, а не до ног сущности.
- **Ограничить дальностью игрока:** включено по умолчанию; минимум выбранной дальности и `player.entityReachBlocks()`.
- **Сквозь блоки:** отключает учёт блоков в луче. Не позволяет проходить сквозь серверные проверки. При выключении ударить цель за блоком скрипт не должен.
- **Криты → Обычные:** не ждать условий крита, но соблюдать заряд и остальные ограничения.
- **Только криты:** ждать падения, положительной высоты падения и заряда больше 0.9; не атаковать на земле, при спринте, в жидкости, на лестнице, в транспорте, полёте, с элитрами, рывком трезубца, слепотой, левитацией или медленным падением. Это консервативная клиентская эвристика, не подтверждение критического урона в Minecraft 26.3. Криты по неживым целям не выполняются.
- **Умные криты:** на земле без пробела разрешён обычный удар; в прыжке/падении или при зажатом пробеле ждать тех же условий крита. В воде/транспорте и других запрещённых состояниях в воздухе обычного fallback нет.
- **Только с пробелом:** отдельное обязательное условие для всех режимов. Не прыгает автоматически. Совместно с умными критами фактически требует критические условия.
- **Заряд удара:** минимум 0.1–1.0; в критических режимах крит всё равно требует больше 0.9.
- **Мин. интервал:** дополнительный промежуток между попытками атак.
- **Удержание прицела:** непрерывное наведение на одну UUID перед атакой. Таймер сбрасывается при смене/потере/исключении цели и при паузе. После удара заново не отсчитывается: это задержка захвата, не межударный интервал.
- **Пауза при использовании предмета:** не прерывать еду/щит/лук, включено по умолчанию.
- **Только меч или топор:** проверка суффиксов ID `_sword` / `_axe`, не включает копья, булавы и инструменты других типов.
- **Только при зажатой ЛКМ:** дополнительное условие. Не блокирует обычные ручные атаки Minecraft.

Всегда действует пауза при открытом экране, потере фокуса, заблокированном вводе, смерти и spectator. Бот не поворачивает камеру, не прыгает, не сбрасывает спринт и не подменяет инвентарь. Для критов спринт нужно прекратить самостоятельно; AutoSprint может мешать.

## Границы «всех сущностей»

Выбор «Неживые» позволяет попытаться ударить сущность, которую возвращает raycast API (например, кристалл). Не каждую сущность Minecraft можно ударить: предметы, опыт, снаряды и другие объекты могут не иметь подходящего для raycast хитбокса или сервер может игнорировать атаку. Скрипт не меняет это поведение.

Сначала луч выбирает первую сущность, затем применяются фильтры. Исключённая цель не должна становиться прозрачной для атаки по другой сущности за ней.

## План проверки в клиенте

Проводить с выключенными остальными боевыми модулями, без ручных кликов, если не тестируется ЛКМ.

- [ ] Файл компилируется; в Combat ровно один ScriptTriggerBot; после перезагрузки нет конфликта имён.
- [ ] Выключение модуля полностью прекращает автоматические удары.
- [ ] Без наведения, при пустом выборе категорий, в меню/чате и при потере фокуса ударов нет.
- [ ] Каждая категория включается отдельно; друг/невидимый/бот/стойка исключаются своими переключателями.
- [ ] Белый список `zombie` пропускает только зомби среди выбранных категорий; чёрный исключает; пустой белый список никого не пропускает.
- [ ] При запрещённой сущности перед разрешённой не атакуется задняя.
- [ ] Дальность проверена внутри и снаружи границы; ограничение реальной дальностью включается отдельно.
- [ ] За сплошным блоком без «Сквозь блоки» атак нет. С ним наличие попытки не путать с принятым сервером уроном.
- [ ] Обычный режим атакует на земле; строгий не атакует на земле/подъёме/спринте, атакует при допустимом падении и заряде.
- [ ] Умные криты бьют на земле без пробела, ждут падения при прыжке; отдельно проверить удержание Space после приземления.
- [ ] «Только с пробелом» запрещает автоматические удары при отпущенной клавише во всех режимах.
- [ ] Вода, лестница, транспорт, эффекты, элитры: критические режимы не дают неподходящие удары.
- [ ] Удержание прицела сбрасывается при смене/потере цели; интервал и заряд соблюдаются независимо.
- [ ] Пауза еды/щита и ограничение мечом/топором работают; переключатели можно отключить.
- [ ] Вход/выход из мира, смерть и перезагрузка скрипта не дают ошибок в консоли.

Для исправления прислать версию API, текст ошибки и настройки/действия для воспроизведения. Даже успешная компиляция не подтверждает корректность критов на конкретном сервере.
