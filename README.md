# Скрипты для Brokke.cc

Репозиторий документации и будущих Kotlin-скриптов для Brokke.cc.

## Источники

- [API.md](API.md) — руководство: синтаксис, события, настройки, ограничения и интеграции.
- [API_REFERENCE.txt](API_REFERENCE.txt) — сигнатуры функций и типы. При разработке проверять конкретные вызовы здесь.
- [EXAMPLES.kts.txt](EXAMPLES.kts.txt) — сборник отдельных примеров, а не один готовый скрипт. Разделители имеют вид `// Имя.kts`.
- `scripts_config.json` — в исходном состоянии содержит `{}`; схема в этом файле не описана.
- `mcp.properties` — локальная конфигурация MCP. Содержит токен доступа: не копировать его в скрипты, логи и инструкции. Если он был опубликован, заменить через настройки клиента. Удаление из текущей версии Git не удаляет его из истории.

## Модель скриптов

По предоставленной документации:

- Язык Kotlin, расширение `.kts`; один файл — один скрипт.
- Установка: `.minecraft/brokke/scripts`, либо кнопка «Папка» во вкладке «Скрипты».
- Сохранение файла вызывает перекомпиляцию/перезагрузку. Имя файла без расширения — ID.
- Имя, описание, автор, версия и настройки объявляются на верхнем уровне; логика — в обработчиках. Документация указывает API 4 (`requireApi(4)`).
- Состояние включения, настройки и бинд сохраняются клиентом.
- Основной шаблон: `on<ClientTickEvent> { if (!inGame) return@on; ... }`.
- Есть `onEnable`, `onDisable`, `onUnload`; подписки событий работают при включённом скрипте.

### Доступные направления

Игрок, мир, сущности, блоки, инвентарь и контейнеры; ввод, взаимодействие, повороты и пакеты; чат и команды; настройки и бинды; 2D/3D-рендер, HUD, окна, шейдеры и графики; таймеры, корутины и очереди кликов; хранилище, ассеты и обмен данными скриптов; модули клиента; друзья, точки, навигация; HTTP, скриншоты, Discord и Telegram; профилирование.

### Ограничения и правила разработки

- Не писать `import`; API предоставлен окружением. Запрещены `net.minecraft.*`, `java.io`, `java.nio.file`, `java.net`, потоки, `Thread.sleep`, рефлексия, `System.exit`, `ClassLoader`.
- Обработчик дольше 250 мс или пять ошибок подряд выключают скрипт.
- Не использовать блокирующее ожидание и тяжёлые обходы мира каждый тик. Для ожиданий — `launch`, `waitTicks`, `waitUntil`, таймеры.
- По документации ожидания корутин при выключении стоят на паузе. Освобождение зажатых клавиш и восстановление изменённого состояния проектировать явно.
- HTTP: только HTTP(S), ответ до 4 МБ, таймаут до 60 секунд, максимум шесть одновременных запросов на скрипт.
- Не встраивать токены Telegram, Discord webhook и MCP в публикуемые файлы. Сетевые отправки и скриншоты делать только по явному запросу владельца.
- Проверять `Float`/`Double`/`Int`, наличие мира, таймауты и конфликты имён модулей.

## Примеры в исходном сборнике

TargetHud, ChatCommand, AutoSprint, FastFly, QuickMenu, ServerHud, AutoEat, Events, WebCheck, ServerGraph, DeathShot, TelegramRemote. Каждый фрагмент нужно выделять в отдельный `.kts`; сетевым примерам нужна отдельная проверка настроек и доступа.

## Как будем работать

1. Уточнить поведение скрипта, версию клиента, настройки и бинд; для серверной логики — сервер и его правила.
2. Хранить готовый код в `scripts/<id>.kts`, инструкции и ограничения — рядом или в документации.
3. Сверять вызовы с предоставленными API и примерами, не выдавать предположения за существующие функции.
4. Проверять в клиенте компиляцию и поведение, затем исправлять по точному тексту ошибок. Без клиента возможна только статическая проверка, не полноценный тест.
5. Коммитить/публиковать изменения по запросу владельца в текущей рабочей ветке. Не публиковать секреты.

## MCP

В исходном конфиге сервер выключен (`enabled=false`). В документации описаны чтение API и примеров, список и исходники скриптов, развёртывание с компиляцией, включение/выключение, настройки, логи, ассеты, модули и состояние игры.

Наличие `mcp.properties` само по себе не подключает эту среду к клиенту на компьютере владельца. Здесь нет подтверждённого доступа к игровому MCP; локальный порт компьютера не является портом этой удалённой среды. Токен для работы с GitHub не требуется сообщать в чате.
